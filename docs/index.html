Spec-driven dev with four agents, and you in the loop.

squad is a reusable, project-agnostic development framework. A product manager, designer, monetization strategist, and engineer hand off through reviewable Markdown artifacts — and no phase moves forward until you approve it.

01Install

Works in Claude Code, OpenCode, Copilot CLI, Cursor, Windsurf, Codex — and any AGENTS.md tool. One canonical source, projected into each.

Claude Code — native plugin:

>/plugin marketplace add phoinixi/squad
>/plugin install squad@squad

Every other tool — one command in your project:

$npx github:phoinixi/squad setup opencode

Swap opencode for copilot, cursor, windsurf, or codex. Then run the init-framework step and start with discover <idea>.

02The workflow

Five phases. Each is one slash command. Nothing auto-chains.

/discover
→ spec.md
/design
→ design.md
/monetize
→ monetization.md · optional
/plan
→ plan.md + tasks.md
/build
→ code, one task at a time

Between every phase you review the artifact and run /approve — which flips its Status: draft line to approved. The next phase refuses to run until it does.

03The four agents

One owner per phase. Each writes only its own artifact.

Product Manager

Requirements, scope, priorities, success metrics.

spec.md

Product Designer

UX, user flows, design specs.

design.md

Monetization Strategist

Pricing, business model, revenue. Optional.

monetization.md

Software Engineer

Architecture, plan, task breakdown, code.

plan.md · tasks.md · code

04Why four agents, not one?

A single mega-agent loses the thread across a long build. squad's agents hand off through files in .framework/, not chat history — so context persists across phases, each role stays tight and accountable, and you have a reviewable paper trail at every checkpoint. This very site was built by running squad on itself; the artifacts live in .framework/squad-docs/.
